**两个文件夹里各有一份 `先读我.md`** —— 从那里进。

想快速查仓库内某个文件的用途，打开[项目文件索引](给我看的/项目文件索引.md)。

## 三种情况，看哪一个

### 情况 A：接手迭代（给 AI）

传 **`给AI看的\给AI的完整说明书.md`** → 再传 **`给AI看的\单文件版-工程版.md`**。

> ⚠️ **别传 `单文件版-全内容.md`** —— 它含人格正文，新窗口看到会**直接拒答**，
> 连打包、改配置这类工程活也一起不干（实测踩过，见坑 25）。

### 情况 B：自己用

`给我看的\操作手册.md`（日常操作 + 怎么提问）、`给我看的\人格写作模板.md`（自己写人格）。

### 情况 C：在新电脑上重建

1. **第 0 步：不是 E 盘就先双击 `改路径.bat`**（或 `python setup_paths.py D:\本地ai`）
   —— 包里三种编码混用，**必须用这个工具改，手工替换会把文件写坏**。
2. 读 `给AI看的\01-系统总览.md` —— 看目标机器要求（**显存 8 GB 是硬门槛**）
3. 读 `给AI看的\02-技术踩坑档案.md` —— **这一步最重要**，不看会重复踩坑
4. 按 `给AI看的\03-文件与脚本说明.md` 里的顺序执行

## 包里的路径怎么读（坑 23 的教训）

- **裸文件名**（`02-技术踩坑档案.md`）表示"本交付包里的某个文件" —— 包里同名文件唯一。
- **带路径的写法一律相对 `交付包\`**。
- 脚本在 `scripts/` 子目录，所以 `python scripts\astrbot_setup.py` 这种写法**在本包根目录下有效**。
  在**项目根 `C:\LocalAI-Assistant\`** 下，脚本同时存在于根和 `scripts\`（后者是镜像，由
  `scripts_sync.py` 生成并校验），所以两种写法都能跑。
  改脚本**一律改项目根那份**，然后跑一次 `python scripts_sync.py`。
- `.bat` 只有交付包 `scripts\` 和项目根各一份（内部全是硬编码绝对路径，放哪都一样）：
  双击 `启动AstrBot.bat`。

## 最重要的五条经验

如果只看五句话：

1. **GGUF 的 chat 模板会拒绝多条 system 消息**，导致任何正常前端都报 400。
   必须用 `scripts/patch_template.py` 打补丁（等长原地覆盖，不重写文件）。

2. **强人格会让模型拒绝调用工具。** 要把"搜索"写成**角色的内在动机**，
   而不是外部规则。实测改这一处，工具调用从 0/2 变成 5/5。

3. **中文 Windows 上的 .bat 必须存成 GBK + CRLF**，用 UTF-8 或 LF 会让 cmd 吃字符，
   报一堆 `not recognized`。

4. **Cherry Studio 的"当前模型"至少有 4 个存放位置**，其中 `agent` 表最容易被漏掉。
   见 `scripts\cherry-legacy\fix_agent_model.py` 与坑 13（**已归档，跑不了** —— Cherry 已卸载）。
   现在只有 AstrBot 一个前端、一个模型实例，不存在"绑错模型"的问题。

5. **Windows 的用户级环境变量对"已经运行"的进程无效。**
   让程序把数据写到别的盘（比如 `ASTRBOT_ROOT`），
   光设注册表不够 —— **启动脚本里必须自己 `set` 一遍**，否则它会写回 C 盘。
   见坑 14 与 `05-AstrBot界面.md`。

详见 `02-技术踩坑档案.md`。
